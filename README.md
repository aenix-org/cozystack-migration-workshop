# Миграция с VMware на Cozystack: воркшоп и лабораторные

Материалы для тех, кто администрирует VMware и хочет понять, что такое Cozystack —
не по презентации, а руками.

Kubernetes знать не нужно. Всё объясняется по ходу, через то, что вы уже знаете по vSphere.

## Что здесь есть

### [`workshop/`](workshop/) — основной воркшоп

Живая миграция приложения из vSphere. Три виртуалки — приложение, база, очередь — за
несколько часов превращаются в приложение на Cozystack с управляемыми базой и очередью
из каталога.

Проходится с ведущим, за один день. Материалы — пошаговые сообщения для чата,
манифесты и скрипты.

### [`labs/`](labs/) — пятнадцать лабораторных

Проходятся самостоятельно, в своём темпе, дома или в перерывах. Каждая — со своим
скриптом проверки.

рассчитан на один присест: берите по одной за вечер.

Лабы 0–4 — тренировка на безобидном приложении. С пятой начинается сквозная рабочая
задача: выкатить внутренний сервис «Пропуск» — сотрудник заказывает пропуск для гостя,
охрана видит список, руководство смотрит отчёт. Каждый сервис появляется из-за конкретной
боли, а не потому что настала его очередь.

### [`check/`](check/) — проверка своими руками

В каждой лабе есть `check.sh`. Запускаете сами, когда захотите:

```bash
cd labs/03-scale
./check.sh
```

Скрипт проверяет не «файл применён», а что оно **работает по сути**, и складывает рядом
отчёт-артефакт. Отчёт можно приложить куда угодно — в чат сообщества, в заявку на
сертификацию, себе в заметки.

## С чего начать

1. Получите доступ к тенанту — на воркшопе его выдаёт ведущий, самостоятельно
   регистрируйтесь через сообщество.
2. Поставьте `kubectl` — как именно, написано в [начале воркшопа](workshop/chat-posts.md).
3. Заберите этот репозиторий: в нём лежат манифесты и скрипты проверки, они понадобятся
   с первой же лабы.

   ```bash
   git clone https://github.com/aenix-org/cozystack-migration-workshop.git
   cd cozystack-migration-workshop
   ```

4. Пройдите [лабу 0](labs/00-cluster/) — она заведёт вам площадку для всего остального.

Дальше по порядку. Лабы можно проходить вразнобой, но 1–4 связаны одним приложением, а
5–14 — одной задачей, так что подряд будет понятнее.

## Если что-то не работает

Первым делом проверьте `echo $KUBECONFIG` — переменная задаётся заново в каждом новом
окне терминала, и это самая частая причина странного поведения.

Дальше — запустите `check.sh` той лабы, на которой застряли: он скажет, что именно не так
и что с этим делать.

Если не помогло — приходите в сообщество, приложив отчёт скрипта.
